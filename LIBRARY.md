# Moon Toybox 0.1.0

## Progressive live icons (current website default)

`upgradeTo3D` defaults to bounded 3D rotation (±30°), with shape-specific speed multipliers: moon 0.65, truck 1.05, teddy 0.75, knot 1.15, relative to the 0.18 rad/s phase rate. Initial tilts are −8°, −5°, +8°, −12° respectively. No page-specific configuration is needed. Override via `data-rotation-speed`, `data-rotation-limit` (degrees), and `data-rotation-tilt` (degrees) on the source image. Reduced-motion and offscreen/hidden-page suspension are preserved. These defaults apply to the progressive helper; low-level `mountMoon3D` remains explicitly controlled.

WebP low→high is a loading cover, not a replacement for 3D. `import {upgradeTo3D} from "moon-toybox/progressive"; const stop3D=upgradeTo3D(document,{base:"/fields/"});` dynamically loads WebGL while images remain visible; mounts sequentially near viewport, renders matching initial pose, then crossfades via .moon-live.ready. Website CSS supplies stacking and .35s transition; copy its .moon-live rules to the consuming app. Pointer movement rotates live icons. Failure retains WebP; cleanup disposes contexts and restores images. SVG mode suspends 3D. This version uses one context per live icon (avoid huge grids); future shared-renderer atlas may be preferable. Old no-WebGL-startup acceptance applies only to image-only use, not the updated website.


Reusable image-first lunar icon kit. Four current assets: moon, truck, teddy, knot. Legacy sphere/ring fields remain available through the low-level renderer. Preserves the pearl shaders, closed-mesh SDF pipeline, translucent rear shading and rotation-driven optical flashes separately from lightweight icons.

## Install

`npm install ./moon-toybox-0.1.0.tgz`

Copy `node_modules/moon-toybox/icons` to your site's `/icons`. Raster and SVG have transparent backgrounds. Low-res WebP is 48², high-res WebP is 384². Recommended displayed sizes 24–160px, not fullscreen.

```html
<img src="/icons/moon-low.webp" data-moon-icon="moon"
     width="48" height="48" alt="Moon Toybox">
```
```js
import { upgradeIcons, createIcon, assets } from 'moon-toybox';
const stop = upgradeIcons(document, { base: '/icons/' });
// loads low first, decodes high near viewport, then swaps without layout shift.
// stop() cancels observation and pending swaps.
```

Without JavaScript the initial low-resolution image remains usable. High failures preserve low. Supply width/height and alt; use alt="" when decorative. A standard `<img src="/icons/moon-high.webp">` works independently of the library.

SVG files are manually constructed vector approximations, NOT exact vector conversion of the shader. They use simple paths, gradients and crater circles. SVG has no 3D runtime or external resource dependencies. Torus/knot overlap approximations differ from WebGL.

## Optional 3D

Install `three@0.180.0 three-mesh-bvh@0.9.1`. Copy packaged `fields` to `/fields`.

```js
const { mountMoon3D } = await import('moon-toybox/webgl');
const view = await mountMoon3D(element, {
  shape: 'moon', base: '/fields/', size: 96,
  iridescence: 1.43, opacity: .82
});
view.setRotation(.2, .4);
view.dispose();
```

Do not import `/webgl` for ordinary icons. There is no automatic animation or render loop in mountMoon3D; application controls rendering by rotation updates. One context per explicitly mounted icon: use sparingly, prefer raster for lists. WebGL2/3D-texture support required; on failure retain raster fallback in application.

Other exports from `/webgl`: createPearlMaterial, applyPearl, createSDFPearl, bakeMesh, collectMeshPositions. Source shader module and Worker are included; bundler must support module Workers (Vite verified). Static closed consistently oriented meshes only; no skins/morphs. SDF representation is not cheap merely because its raster proxy is 80 triangles. Translucency is approximate; optical rays are stylized screen-space glints, not physical volumetric scattering.
